# SmartFlow Beauty: чек-лист выпуска

Версия приложения: `0.1.0-alpha`  
Назначение: первый внешний пилот  
Правило: каждый выпуск проходит все пункты по порядку; пропущенный обязательный пункт останавливает выпуск.

## 1. Подготовка

- [ ] Рабочее дерево Git чистое, нужный коммит выбран и его hash записан.
- [ ] Значение в `VERSION` совпадает с `SMARTFLOW_VERSION` в `AppsScript/Version.gs`.
- [ ] В `CHANGELOG.md` описаны изменения выпуска и известные ограничения.
- [ ] Создана резервная копия рабочей Google-таблицы перед миграциями.
- [ ] Проверено, что в Git нет `.clasp.json`, токенов, Telegram ID клиентов и реальных выгрузок салона.
- [ ] Строк `ClientBotToken` и `AdminBotToken` нет в Settings, а оба токена находятся только в Script Properties.

## 2. Локальная проверка

```text
node Scripts/validate-project.mjs
node Scripts/run-tests.mjs
git diff --check
```

- [ ] Валидатор завершился без ошибок.
- [ ] Все автоматические тесты прошли.
- [ ] `git diff --check` не нашёл ошибок пробелов и конфликтных маркеров.

## 3. Публикация Apps Script

Для клиентского production-профиля из корня репозитория предпочтительно выполнить:

```text
.\Scripts\deploy-client.cmd -Client salon-alice
.\Scripts\deploy-client.cmd -Client salon-alice -Push
```

Первая команда выполняет preflight без загрузки. Вторая требует точного подтверждения имени профиля и запускает `clasp push`. Реальный Script ID хранится только в игнорируемом Git файле `deployments/salon-alice/deployment.local.json`.

Из каталога `AppsScript` выполнить:

```text
clasp status
clasp push
```

- [ ] `clasp status` указывает на правильный Apps Script project ID.
- [ ] `clasp push` завершился без ошибок.
- [ ] Создана новая версия deployment, а не только сохранён исходный код.
- [ ] Production Web App deployment указывает на новую версию.
- [ ] URL deployment заканчивается на `/exec` и совпадает с `AppsScriptUrl`.

## 4. Миграции и инфраструктура

- [ ] Выполнены только миграции, указанные для этого выпуска в deployment guide или changelog.
- [ ] Для существующей установки выполнена `migrateBotTokensToScriptProperties()`.
- [ ] После переноса токенов выполнена `migrateRemoveLegacyBotTokenSettings()`.
- [ ] Каждая миграция завершилась без ошибки; повторный запуск безопасен.
- [ ] Проверены triggers `send24hAppointmentReminders` и `syncCompletedCustomerVisitsTrigger`.
- [ ] Нет дублирующихся triggers.
- [ ] Webhooks Client Bot и Admin Bot переустановлены, если изменился deployment URL.
- [ ] `getClientWebhookInfo()` и `getAdminWebhookInfo()` возвращают ожидаемый production URL.

## 5. Health check

В Apps Script вручную выполнить `runSmartFlowHealthCheck()`.

- [ ] `ok` равно `true`.
- [ ] `version` совпадает с выпускаемой версией.
- [ ] `failed` равно `0`.
- [ ] Проверены `SCHEMA`, `SETTINGS`, `CALENDARS`, `WEBHOOKS`, `TRIGGERS` и `REQUEST_RECIPIENTS`.
- [ ] Отчёт не содержит токенов или персональных данных.

## 6. Обязательная регрессия

### Client Bot

- [ ] `/start`, смена языка и локализованные кнопки навигации работают.
- [ ] Новая заявка создаётся; после «Записаться» появляется главное меню.
- [ ] Клиент видит «Мои записи».
- [ ] Перенос показывает обновлённую карточку и сбрасывает поля напоминания и подтверждения.
- [ ] Отмена показывает карточку отменённой записи без action-кнопок.

### Admin Bot

- [ ] `/start` разрешён каждому ID из `AdminTelegramIds` и запрещён постороннему ID.
- [ ] Новая заявка приходит всем администраторам и дополнительным получателям без дублей.
- [ ] Один администратор подтверждает заявку; действие второго не создаёт дубль и убирает устаревшие кнопки.
- [ ] Отклонение заявки работает по тому же правилу.
- [ ] «Мои записи» показывает актуальные bot- и ручные Calendar-события.
- [ ] Клиенты, мастера, услуги, локации, расписания и конфигурация открываются и сохраняются.

### Calendar и фоновые функции

- [ ] Разные мастера могут иметь запись на одно время.
- [ ] Ручное событие блокирует слот только календаря своего мастера.
- [ ] Напоминание за 24 часа отправляется один раз и снова доступно после корректного переноса.
- [ ] Синхронизация завершённых визитов не создаёт дубликаты.

## 7. Решение о выпуске

Выпуск разрешён, только если health check зелёный и нет дефектов потери или дублирования записей.

- [ ] Зафиксированы версия, Git commit, Apps Script deployment version, дата и проверивший человек.
- [ ] При успехе создан annotated Git tag вида `v0.1.0-alpha`.
- [ ] При ошибке выпуск остановлен, deployment возвращён на предыдущую версию и повторно проверены webhooks и health check.
